# Import your data into Linear

Use this guide to plan a safe move from an existing project-management tool to
Linear. Start with a small pilot when you are still evaluating Linear; use the
full migration checklist only after the pilot has been reviewed.

## Choose an approach

### Explore with a pilot

1. Read Linear's [pitch guide](https://linear.app/switch/pitch-guide) and agree on
   the problem the team wants to solve.
2. Follow the [pilot guide](https://linear.app/switch/pilot-guide) with one small,
   representative team.
3. Import a limited sample of active work rather than the complete archive.
4. Ask pilot users to verify assignments, statuses, labels, dates, comments, and
   links before deciding whether to migrate everyone.

### Run a full migration

Follow Linear's [migration guide](https://linear.app/switch/migration-guide) and
use the checklist below to coordinate the move.

## Migration checklist

### 1. Prepare

- Name an owner for the migration and representatives for each affected team.
- Inventory the projects, issues, users, labels, attachments, and history that
  must be retained.
- Remove obsolete test data and decide what should be archived instead of
  imported.
- Map source users, teams, workflows, priorities, and labels to their Linear
  equivalents.
- Record a rollback plan and keep an untouched export from the source tool.

### 2. Test

- Import a representative sample into a test team.
- Confirm that issue titles, descriptions, owners, statuses, dates, comments,
  attachments, and relationships were preserved as expected.
- Document unsupported fields and agree on a manual or automated workaround.
- Ask team representatives to approve the mapping before the production import.

### 3. Migrate

- Announce the migration window and pause edits in the source tool.
- Create a final export immediately before importing.
- Run the import once, record its start and completion time, and save any error
  report produced by the importer.
- Reconcile the source and destination counts for projects, issues, and users.

### 4. Validate and launch

- Spot-check recently updated, old, completed, and linked issues.
- Confirm workspace permissions and integration access before inviting everyone.
- Tell users where new work should be created and keep the old tool read-only for
  the agreed retention period.
- Track missing data or mapping problems in a dedicated Linear project until all
  migration follow-ups are closed.

## Ongoing synchronization

If both tools must remain active, define which system owns each type of data and
which fields synchronize. Avoid allowing the same field to be edited in both
systems unless the integration documents how conflicts are resolved. Test create,
update, delete, and permission changes before enabling synchronization for the
whole organization.
